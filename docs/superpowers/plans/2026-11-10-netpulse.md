# NetPulse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-user web app on a Windows admin PC that pings, port-checks and SNMP-polls hand-added devices every few seconds and pushes every state change live to a React dashboard and event log.

**Architecture:** One FastAPI process: an asyncio `Monitor` runs one task per device, each cycle runs checker strategies (ping, TCP, SNMP), feeds a pure state machine and change tracker, and publishes to an in-process event bus. Subscribers persist events to SQLite and fan out to Server-Sent Events clients. React (Vite, React-Bootstrap) loads `/api/status` once, then applies SSE messages through a reducer.

**Tech Stack:** Python ≥ 3.12, FastAPI, Uvicorn, SQLAlchemy 2 (sync, SQLite), Pydantic 2, pysnmp 7 (lextudio, asyncio hlapi), cryptography (Fernet), pytest + pytest-asyncio + httpx · Node ≥ 20, React 18, Vite, React-Bootstrap + Bootstrap 5, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-netpulse-design.md` (vault mirror `01-Projects/NetPulse/02-design.md`). Read it before starting any task.

## Global Constraints

- Server binds `127.0.0.1:8765` by default; overridable by env `NETPULSE_HOST`, `NETPULSE_PORT`; data dir `NETPULSE_DATA_DIR` (default `<repo>/data`).
- DB file `data/netpulse.db`; Fernet key `data/secret.key`, created on first run. `data/` is git-ignored.
- Defaults per device: `interval_s=5`, `fail_threshold=2`, `timeout_ms=1000`, `liveness="ping"`, `snmp_port=161`.
- Validation limits: ports 1–65535; `interval_s` 2–3600; `fail_threshold` 1–10; `timeout_ms` 200–10000 and `< interval_s*1000`; OID matches `^\.?\d+(\.\d+)+$`; host is an IP or RFC 1123 hostname.
- Device statuses: `UNKNOWN`, `UP`, `DEGRADED`, `DOWN`, `PAUSED`. Events only on change, never per poll.
- Event kinds: `status_change`, `reboot`, `if_change`, `oid_change`, `oid_threshold`, `check_error`. Severities: `info`, `warning`, `critical`.
- Severity map: DOWN → critical; DEGRADED → warning; UP/PAUSED → info; reboot → critical; interface down → warning, up → info; OID threshold breach → critical, back to normal → info; OID change → info; check_error → warning.
- Domain Controller preset ports: `53, 88, 135, 389, 445, 636, 3268, 3389`.
- Latency ring buffer: 60 samples per device, in memory only. SSE heartbeat every 15 s; drop a client whose queue exceeds 1000 messages.
- SNMP secrets are write-only through the API (responses carry `has_community`, `has_auth_key`, `has_priv_key`) and never logged.
- No AI attribution in code, comments, commits or docs.
- Commands below are for macOS dev (`.venv/bin/...`); on Windows use `.venv\Scripts\...`.

## Review Focus

1. **Editing a device while its cycle is running** — the old task is cancelled and a late result from it must not overwrite the new state. Test in Task 4 (`test_upsert_during_slow_cycle_discards_stale_result`).
2. **Deleting a device that has events** — the event log must still list them (device_id becomes null, message keeps the name). Test in Task 3 (`test_delete_device_keeps_events`) and Task 5 (`test_delete_device_then_list_events`).
3. **Backend restart or network blip while the dashboard is open** — on reconnect the UI must show current state with no duplicated log rows. Test in Task 6 (`SNAPSHOT replaces devices and events`).
4. **Typos in host** (spaces, `http://`, a leading or trailing dash) are rejected with 422; a well-formed but unresolvable name shows DOWN with reason `dns`. Tests in Task 2 and Task 5.
5. **Everything goes down at once** (admin PC unplugged) — one summarised notification, not twenty. Test in Task 12 (`coalesceAlerts`).
